Crypto-stealing code planted on 178 major websites; flaw reported in Java

In one sentence
Reports claim crypto-stealing code hit 178 major sites and that a Java flaw was found, but neither has a primary source, named victims or technical detail yet.

Two security stories reached the newsdesk on the same day. One says crypto-stealing code has been planted on 178 major websites. The other says a vulnerability has been found in Java. Neither has yet been traced to a primary source such as a vendor advisory, a CVE entry or a regulator notice, so what follows separates what is reported from what is established.

What has been reported

The first claim comes from a Yahoo Finance video and the crypto outlet CryptoProwl. Both say attackers injected code designed to steal cryptocurrency into 178 major websites worldwide. That is all the reporting offers. It does not name the sites, the attackers, the date of the intrusion or the sums taken. The word "major" and the figure of 178 both come from the headlines. Nobody has checked them against an independent count.

That gap matters, because a number like 178 is easy to repeat and hard to audit. It could be 178 separate sites compromised one by one. It could be a single weak link, such as a shared script or a third-party widget, that happened to be loaded by 178 sites. The two cases are very different in cause and in the fix.

Why the pattern is familiar

If the report holds up, it describes a well-known kind of attack, often grouped under the name Magecart. Attackers do not break into a user's computer. They get malicious JavaScript into a page the user already trusts, and the browser runs it as if the site's owner had written it. On a shop checkout, such code can copy card details as they are typed. On a site that connects to a crypto wallet, it can swap a destination address or prompt the user to approve a transfer.

The usual route in is the supply chain. Modern sites pull in analytics, chat tools, ad scripts and code libraries from outside providers. Compromise one of those and every site that loads it inherits the problem. The site's operator may see nothing wrong, since their own servers were never touched.

That is the real concern here, more than the crypto angle. Users have little way to tell a clean page from a tampered one. Site operators often cannot see what their pages load once those pages are running in someone else's browser. Defences exist, including content security policies, subresource integrity checks that pin a script to a known fingerprint, and monitoring of what pages load. Adoption is uneven. Nothing in the current reports says whether the affected sites used any of them.

A separate Java report

The second thread is a report, relayed in the discovery brief from BBC Business, that a security flaw has been found in Java. The brief gives no CVE identifier, no affected versions, no name for whoever disclosed it and no word on whether a patch exists. It describes Java as the world's third-largest programming language. That ranking depends on which index is used, and it has not been checked here.

Java does run a great deal of business software, so a serious flaw could reach far. But reach depends on specifics: whether the bug is in the language runtime or in a popular library, whether it can be exploited remotely, and whether fixes are out. Without those details, calling it a major exposure would go beyond the evidence.

Nor is there any link between the two stories. No source ties the website injection to the Java flaw, and the two should not be read as one incident.

What to watch

Three things would settle matters. The first is a primary source for the 178 figure, from a security firm or a victim's disclosure, with named sites and a date. The second is the original BBC report, or the Java maintainers' own advisory, giving a CVE number, affected versions and patch status. The third is any confirmed loss figure for the crypto theft, which would show whether this was a large operation or a mostly theoretical one. Until those appear, both stories remain reports, not findings.
