Critical PHP flaw, reportedly found with AI, sets off a global patching scramble

In one sentence
PHP shipped emergency fixes for two AI-assisted-discovery flaws, rated 9.2, that could let attackers run code on a large share of the web, and IT teams are racing to patch.

The people who run a large share of the world's websites spent this week patching one piece of software. PHP, the programming language that powers an estimated 70% of sites, according to security firm Wiz, shipped emergency fixes on Wednesday for two serious flaws. A PHP Foundation engineer, Volker Dusch, called it the most severe PHP security issue in more than a decade. Both bugs were found with the help of AI models, according to the firms that found them.

The disclosure has set off a scramble among site operators, hosting firms and IT departments, including those in UK public services. The BBC reports that IT staff on the frontline describe the pace as "relentless".

What was found

The two bugs are tracked as CVE-2026-109618 and CVE-2026-109619. Both are memory-safety flaws, and both are rated 9.2 on the CVSS v4 scale. Together they have been nicknamed "PHP2Shell". An attacker with no login can run code on a vulnerable server. Exposure is highest on Apache servers using mod_php, where a malicious request can trigger the flaw before any application code runs.

The reach is wide. Calif, Wiz and Cloudflare say the vulnerable code goes back to PHP 5.4. PHP's own advisory did not name the oldest affected version.

Fixes are in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Backported patches were also published for the unsupported 7.4, 8.0 and 8.1 branches. PHP says configuration changes do not fully replace updating, and calls updating "the only safe choice". WordPress urged site owners to update. It noted that versions before 8.2 no longer receive security fixes, so many older installations have no routine upgrade path.

The AI claim

The AI attribution is credited to the finders themselves, so it is best read as their account. Calif says it found the first bug in August using OpenAI's GPT-5.6 Sol model. The work was part of an audit of PHP's source code that OpenAI funded under its Patch the Planet initiative. Wiz, which is part of Google, says it found the flaws independently, weeks later. It says it used its own Wiz Atlas tool alongside Gemini 4 Argon and GPT-5.6 Sol. PHP's advisory credits Calif, Wiz and OpenAI researchers.

Calif was more cautious than the headlines. It said it used only generally available models and no special tooling. It also said that knowing PHP's history mattered more than the model.

"No model is simply capable of unearthing 'all bugs' with simple prompts. At least for now."

OpenAI, whose model and funding were involved, said it considers this "one of the most impactful security issues in recent memory". That is a vendor describing its own work. The CVE scores and the scale of the patching effort are easier to check than the characterisation.

The scramble

Patching started under pressure. PHP had scheduled its release for 14:00 UTC on 21 October, with a wider embargo lifting the next day. Details leaked on Hacker News, so the project moved the release up. Cloudflare had already switched on protective firewall rules for all customers about nine hours before disclosure. Security firm watchTowr confirmed the bugs were real before any patch existed, and a proof-of-concept exploit then circulated online. Cloudflare saw attackers change their payloads to get around its rules. Fortune reports that AWS saw broad exploitation in the wild, with some attempts before the public disclosure.

The effects were practical. Laravel paused Cloud deployments while it rebuilt on patched images. Pinboard, the GrapheneOS forum and OBS took parts of their sites offline. The UK's National Cyber Security Centre and the EU's CERT-EU advised organisations to take systems offline if they could not patch straight away. The US National Security Agency also issued an alert.

This is where the staffing strain shows. Much PHP is not sitting on one tidy server. It is spread across content management systems, bought-in applications, contractor-run sites and old systems nobody has touched in years. Each needs finding, testing and updating. The BBC's reporting on frontline IT workers describes that burden as nonstop. UK councils and other public bodies, which often depend on small teams and ageing web estates, are among those under strain.

There is a second concern, which I could not confirm in detail from primary sources. Reports say attackers are using AI to study vendor fixes and work backwards to the flaw. If that is right, the gap between a patch appearing and attacks appearing shrinks. The Cloudflare observations above fit that pattern. They do not prove that AI is the cause.

What to watch

Two things matter next. The first is how quickly the long tail of unpatched servers shrinks, especially on branches that no longer get regular fixes. Evidence of widespread compromise, as opposed to attempts, would raise the stakes sharply. The second is whether this is a one-off or a template. AI-assisted audits found a bug in code that has been scrutinised for years. Defenders now have to assume that attackers can do the same, and can do it faster than operators can update.
